Hint: What's the vulnerability?

How does the server know you are logged in right now? Check your browser's developer tools (Application > Cookies). If an attacker steals that exact cookie value using the Stored XSS payload from Page 3, what happens if they inject it into their own browser?

Solution: How to exploit it

Vulnerability: Session Hijacking (via XSS) and Session Fixation

Exploitation:

  1. Drop the payload <script>alert(document.cookie)</script> in the Guestbook (Page 3).
  2. Copy the session cookie value that pops up.
  3. Open a new browser (like Incognito mode) where you are NOT logged in.
  4. Open DevTools, manually set the session cookie to the stolen value.
  5. Navigate to /dashboard. You are now logged in as the victim without knowing their password!

In Vulnerable mode, the session cookie lacks the HttpOnly flag (allowing JS to read it). In Patched mode, the HttpOnly flag is set to true, making document.cookie return nothing for that cookie, thereby blocking XSS-based hijacking entirely.
