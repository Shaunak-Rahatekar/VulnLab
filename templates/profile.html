Hint: What's the vulnerability?

Notice that changing the email only requires an authenticated cookie and a POST request. The server does not check where the request originated from (the "Origin" or "Referer" headers) nor does it require a unique secret token. What happens if a victim visits a completely different website (run by an attacker) that automatically submits a hidden form to this exact endpoint?

Solution: How to exploit it

Vulnerability: Cross-Site Request Forgery (CSRF)

Exploitation:

  1. Make sure you are logged into VulnLab in your browser.
  2. Without logging out, simply double-click the attacks/csrf_attack.html file on your computer to open it in a new browser tab.
  3. The page looks like a spam/prize website, but in the background, it silently submits a form to http://127.0.0.1:5000/change_email.
  4. Because your browser automatically attaches your VulnLab session cookie to the request, the server believes YOU made the request and successfully changes your email to the attacker's email!

The Fix: When Vulnerable mode is off, the form requires an unpredictable csrf_token generated by the server. The attacker's external website cannot guess this token, so their forged request gets rejected by the backend.
