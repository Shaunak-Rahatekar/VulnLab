HTTP Security Headers
CIA Impact: 🟠 Integrity & Confidentiality OWASP: A05:2021-Security Misconfiguration CVSS: 6.5 (Medium)

Security headers provide critical client-side browser hardening. When headers like X-Frame-Options or Content-Security-Policy are missing, applications become vulnerable to UI Redressing (Clickjacking) and script injection.

Hint: What happens without X-Frame-Options?

An attacker can host an invisible iframe of your application on their malicious site, layering deceptive buttons on top (e.g., "Click here to claim $1000"). When the user clicks the bait, they unknowingly click "Confirm Transfer" or "Delete Account" on the framed application.

Solution: How to remediate

Remediation: Enforce response headers on all HTTP replies:

response.headers['X-Frame-Options'] = 'SAMEORIGIN'
response.headers['Content-Security-Policy'] = "default-src 'self'"
response.headers['X-Content-Type-Options'] = 'nosniff'
response.headers['Strict-Transport-Security'] = 'max-age=31536000; includeSubDomains'
